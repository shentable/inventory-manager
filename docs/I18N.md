# i18n 框架约定（所有实现必须严格遵守）

## 目标
web 前端与 Android 壳全面支持中文（默认）/ 英文。默认语言 zh-CN 下
**所有可见字符串、DOM 结构、样式与原版本完全一致**（现有 Playwright e2e 不得break）。

## Web 端框架（gettext 风格，中文原文即 key）

### 文件结构
```
web/js/i18n.js          # 框架：I18N.t / getLang / setLang / fmtDate / fmtDateTime
web/js/i18n/en-core.js  # 通用+组件+API 层英文字典（ui.js / api.js / index.html 用）
web/js/i18n/en-app.js   # 页面层英文字典（app.js 用）
```
index.html 中加载顺序：i18n.js → i18n/en-core.js → i18n/en-app.js → config.js → api.js → ui.js → app.js

### API（挂在 window.I18N，供所有文件用全局 `I18N.t(...)`）
- `I18N.t(key, vars?)` — key 为中文原文字符串；lang=en 时查合并字典
  （en-core + en-app 合并），查不到**原样返回 key**（zh 回退）。
  插值：`I18N.t('共 {n} 项', { n: 5 })`，字典英文用同名占位 `'共 {n} 项': 'Total {n} items'`。
- `I18N.getLang()` — localStorage('sandwich_lang') → navigator.language 嗅探
  （zh* → 'zh-CN'，其余 → 'en'）。e2e 通过 playwright.config.js 的
  `locale: 'zh-CN'` 固定测试环境语言，断言不受嗅探影响。
- `I18N.setLang(lang)` — 写 localStorage、设 `document.documentElement.lang`、更新 document.title
  （`I18N.t('飨拓™库存管理')`），然后 `location.reload()`。
- `I18N.LANGS = { 'zh-CN': '中文', 'en': 'English' }`
- `I18N.fmtDate(d)` / `I18N.fmtDateTime(d)` — zh：'9月1日' / '9月1日 08:30'；en：'Sep 1' / 'Sep 1 08:30'。
  app.js 里现有的「M月D日」拼接函数必须改调这两个。
- 语言切换 UI：由 app.js 在**登录页右上角**和**首页头部**各渲染一个 🌐 chip 按钮
  （样式复用现有 chip），点击弹出现有 UI.chips/confirm 风格的选择（中文/English），
  选定后调 `I18N.setLang`。

### 字典文件格式
```js
/* en-core.js */ window.I18N_EN_CORE = { '中文原文': 'English text', ... };
/* en-app.js  */ window.I18N_EN_APP  = { '中文原文': 'English text', ... };
```
i18n.js 启动时合并为内部字典。两个文件 key 不得冲突（冲突时 en-app 优先，控制台 warn）。

### 替换规则
1. 只替换**用户可见**字符串：页面文本、按钮、toast、confirm、错误提示、placeholder、
   表单项标签、空态/加载文案。注释、console/log、role 枚举值（'staff'）、
   reason chips 的**提交值**（若提交给后端存库的值是中文如 '过期'，则 key 与提交值分离——
   显示用 t()，提交仍用原中文值，检查后端/数据库里 reason 的实际存法再定）保持原样。
2. 纯字面量 → 直接 `t('原文')`。
3. 拼接串（`'共' + n + ' 项'`）→ 改为 `t('共 {n} 项', { n: n })`。
4. 日期格式化函数 → 改调 `I18N.fmtDate/fmtDateTime`。
5. `toLocaleString()` 保持，但接受当前 lang 作为 locale 参数传入。
6. api.js 的错误处理：`data.detail` 为对象且含 `code` 时优先 `t('errcode.' + code)`
   （en-core 里收录已知 code：pair_verification_required / self_review_not_allowed /
   no_comparable_items / count_comparison_changed 等，从 server/tests 与 cloudflare/ 里搜罗）；
   `detail` 为中文纯字符串时先查字典 `t(detail)`（字典收录后端 64 处 detail 原文），
   查不到显示原文。
7. **不得改变任何 DOM id/class/结构**，e2e 用中文文本定位的元素在 zh-CN 下文本必须逐字不变。

## Android 端
- 所有 Kotlin 中**用户可见**中文字符串抽到 `app/src/main/res/values/strings.xml`
  （默认中文），新建 `values-en/strings.xml` 完整对应。
- Kotlin 中用 `getString(R.string.xxx)` / `context.getString(...)`；带参数的用
  `getString(R.string.xxx, arg)`（strings.xml 里 `%1$s`/`%1$d`）。
- 日志（Log.i/Log.w）保持中文不抽。
- 现有 strings.xml 里已有 app_name 等，合并扩充。
- 语言随系统，App 内不提供切换（系统级标准做法）。

## 后端
不改。保持中文 detail 与 detail.code 现状（54+ 测试断言依赖）。
前端按上述第 6 条做映射翻译。

  在 en 字典中都有条目；跑完删除临时脚本）
- 禁止动 server/、cloudflare/、web/e2e/（e2e 只读参考）
